# OnlineLyra

**Structure-Aware Streaming Forecasting & Causal Evaluation for Solar Power Generation**

![Python 3.9+](https://img.shields.io/badge/python-3.9%2B-blue.svg)
![Dependencies](https://img.shields.io/badge/dependencies-zero%20(stdlib)-brightgreen.svg)
![Protocol](https://img.shields.io/badge/evaluation-block--prequential-orange.svg)

`OnlineLyra` is a lightweight Python project for online time-series forecasting, with photovoltaic (PV) power generation as a primary application.

The project is motivated by a simple question:

> *Can we explicitly extract structural information from a time series, allowing a lightweight neural network to focus on learning the residual rather than the entire signal?*

The underlying idea is to separate predictable structure from variations that are more difficult to model analytically. We explore how analytical methods and lightweight neural learning can complement each other under changing operating conditions.

In streaming environments, structural estimation, forecasting, and online adaptation must use only the information available at the corresponding prediction time.

This repository provides the standalone evaluation-protocol module from that research: causal streaming evaluation, reference forecasting baselines, synthetic PV data generation, and diagnostic metrics.

The PyTorch hybrid models, which combine analytical extrapolation with online residual learning, are developed in a private research branch alongside the TSLib-based deep-learning comparison pipeline. We plan to merge these components into the public repository after the ongoing review is complete.

## Features

- **Strictly causal evaluation:** Maintains temporal separation between historical observations and future prediction targets.
- **Block-wise online learning:** Supports multi-step forecasting with model updates after each completed prediction block.
- **Runtime validation:** Checks timestamp ordering, sampling intervals, and forecast boundaries.
- **Forecasting metrics:** Computes MSE, MAE, RMSE, and NMSE, together with daytime and tail-error diagnostics.
- **CSV evaluation:** Scores prediction logs generated by external forecasting pipelines.
- **Lightweight implementation:** Uses Python 3.9+ and the standard library, with no external dependencies.

## Quick Start

**Requirements:** Python 3.9+. No package installation is required.

Run the streaming benchmark from the repository root:

```bash
python3 -m examples.run_streaming_benchmark
```

The example generates a synthetic PV power series at 15-minute resolution and evaluates three classical baselines: last-value persistence, seasonal persistence, and rolling mean. The stream incorporates diurnal generation patterns, varying daily amplitudes, temporally correlated cloud attenuation, and zero nighttime output.

**Default configuration:**

| Parameter | Value |
| --- | --- |
| Data length | 14 days |
| Initialization period | 3 days |
| Lookback window | 2 days |
| Sampling interval | 15 minutes |
| Plant capacity | 50 MW |
| Forecast horizons | 4, 12, 24 steps (1, 3, 6 hours) |

## Evaluate Your Own Predictions

`OnlineLyra` evaluates prediction logs exported from other forecasting pipelines.

Generate an example prediction file using a new output path:

```bash
python3 -m examples.run_streaming_benchmark \
  --export-csv /tmp/pv_predictions.csv
```

Evaluate the exported predictions:

```bash
python3 scripts/evaluate_csv.py \
  /tmp/pv_predictions.csv \
  --interval-minutes 15 \
  --capacity 50.0
```

The default export contains last-value persistence predictions at a horizon of four steps. To export a different condition, add `--export-model DiurnalSmartPersistence --export-horizon 12` to the benchmark command.

**Expected CSV format:**

```csv
timestamp,target,prediction
2020-01-04T00:00:00+00:00,0.0,0.0
2020-01-04T00:15:00+00:00,0.0,0.0
```

- Timestamps use ISO-8601 formatting and form a strictly increasing, regularly sampled sequence. UTC is recommended.
- Invalid timestamps, malformed rows, and irregular sampling intervals raise validation errors without interpolation.
- For NMSE, supply the initialization-period population variance with `--initialization-variance <float>`.
- Observations, predictions, and plant capacity use the same power unit; the example above uses MW.

## Using a Custom Forecasting Model

Custom models integrate through the `StreamingForecaster` interface:

```python
from typing import List, Sequence
from models.base import StreamingForecaster


class CustomForecaster(StreamingForecaster):
    def predict(
        self,
        lookback_window: Sequence[float],
        horizon: int,
    ) -> List[float]:
        forecast = [lookback_window[-1]] * horizon
        return self.clip_physical_bounds(forecast)

    def update(
        self,
        lookback_window: Sequence[float],
        observed_target: Sequence[float],
    ) -> None:
        # Adapt model state after observing the completed target block.
        return None
```

For example, connect the model to the generated PV stream:

```python
from examples.run_streaming_benchmark import generate_stream
from exp.prequential_runner import BlockPrequentialEvaluator

timestamps, values = generate_stream(days=14, capacity=50.0, seed=42)
model = CustomForecaster(capacity=50.0)
evaluator = BlockPrequentialEvaluator(
    model,
    lookback_steps=192,
    horizon=4,
)
results = evaluator.run(
    timestamps,
    values,
    initialization_steps=288,
)
print(results.summary())
```

The evaluator coordinates predictions, observations, scoring, and model updates. Each independent model–horizon condition uses a fresh model instance.

## Evaluation Protocol

`OnlineLyra` follows a block-prequential evaluation procedure:

1. **Forecast:** Generate predictions using available historical observations.
2. **Observe:** Receive the ground-truth values after the prediction horizon completes.
3. **Evaluate:** Compute forecasting errors for the completed prediction block.
4. **Update:** Adapt the model using the newly observed data.

Model updates occur after the corresponding prediction block has been evaluated. Historical inputs precede the prediction boundary, while target observations belong to the subsequent forecast horizon. Incomplete blocks at the end of a series are excluded from scoring and updates.

Offline initialization and hyperparameter selection use the designated pre-deployment period. The NMSE scoring scale is fixed from the initialization period throughout evaluation.

## Evaluation Metrics

| Metric | Description |
| --- | --- |
| **MSE** | Mean squared error |
| **MAE** | Mean absolute error |
| **RMSE** | Root mean squared error |
| **NMSE** | MSE normalized by initialization-period population variance |
| **P95** | 95th percentile of absolute errors (% of plant capacity) |
| **P99** | 99th percentile of absolute errors (% of plant capacity) |

MSE uses squared power units, MAE and RMSE use power units, and NMSE is dimensionless. P95 and P99 use linearly interpolated percentiles.

Metrics are calculated over both the complete evaluation period and active generation periods. Active generation is defined as:

```text
y_t > 0.01 C
```

where `C` is the nominal plant capacity. Reporting both subsets separates daytime forecasting behavior from nighttime zero-generation periods. P95 and P99 complement the mean scores by highlighting large prediction errors.

## Testing

Run the unit test suite:

```bash
python3 -m unittest discover -s tests -v
```

The tests cover:

- Temporal separation between historical inputs and prediction targets
- Non-overlapping prediction blocks and prediction–scoring–update ordering
- Initialization-period independence from future observations
- Initialization-based variance normalization
- Metric calculations and degenerate edge cases
- CSV validation and round-trip consistency

## Research Direction

`OnlineLyra` explores structure-aware forecasting under streaming constraints. The broader research combines analytical representations of time-series structure with lightweight neural residual learning, examining the trade-offs between forecasting accuracy, computational efficiency, and adaptation to changing temporal patterns.
